# Blueprint：办公文档（office-studio）

> 沉淀日期：2026-08-23 | 来源：office-studio 工作流实战（v1.6 机制）
> 复用方法：同类领域（文档类多智能体工作流）新需求 → 说「复用 办公文档 拓扑」，澄清只问差异，不重新设计。

## 一、拓扑图

```
一句话触发（"帮我做一份商务风PPT"）→ orchestrator（大脑·策划调度）
  ├─ 澄清需求 + 选风格（shared/style-catalog.md）→ 产出 outputs/plans/plan-NN.md
  ├─ 派发自包含任务包（按 doc_type 只派一个）
  ├─ word-crafter   → outputs/word/doc-NN.docx   （Word 撰写·专家小组制）
  ├─ slide-designer → outputs/ppt/deck-NN.pptx   （PPT 设计·专家小组制）
  └─ sheet-analyst  → outputs/excel/sheet-NN.xlsx（Excel 报表·单一资深）

编辑模式：拖入现有 .docx/.pptx/.xlsx → orchestrator 读取识别 → outputs/plans/edit-NN.md
          → 对应专家增量修改（保留原风格/keep 项）→ 产出 + 逐条改动清单（不覆盖原文件）
```

## 二、智能体清单

| 名称 | 一句话职责 | 形态 | 知识库类型 |
|------|-----------|------|-----------|
| orchestrator（大脑） | 吃需求 → 吐已选风格+自包含任务包 → 汇总交付 | 单一资深（调度岗） | 全内置 |
| word-crafter | 吃 plan+风格 → 吐规范 .docx | 专家小组制（主编+内容架构师+语言润色+规范把关） | 内置工艺+刷新型风格 |

## 三、设计决策记录（ADR）

### ADR-01: 拓扑拆分（3 专精 + 共享风格库）
- 状态: 已采纳
- 决策: Word/PPT/Excel 各一个专精专家；风格作为 `shared/style-catalog.md` 共享库，不设独立风格专家
- 理由: 阶段边界=智能体边界——三类产物类型完全不同（docx/pptx/xlsx），各自需要独立工艺方法论与质检；风格是跨文档横切关注点，独立专家会重复造轮子、增加延迟
- 备选: 4 专精（加风格设计师）——被否：风格更适合共享库 + 大脑选风格
- 影响: 新增文档类型（PDF/思维导图等）时按同模式加专精即可，风格库三端规格同步补

### ADR-02: 专家形态（Word+PPT 小组制，Excel 单一资深）
- 状态: 已采纳（用户抉择）
- 决策: 主观岗位（写作/设计）用专家小组制，结构化岗位（数据分析）用单一资深专家
- 理由: 多智能体互评在主观任务上降幻觉、提质量（社区先例 MultiAgentPPT 均多角色）；Excel 流程明确（清洗→计算→图表→结论），单一资深 + 强质检清单省 token、口径统一
- 备选: 全小组制（token 高、延迟长）／全单一资深（主观任务质量上限低）——用户选了推荐平衡项
- 影响: 小组制含协商机制（主角色出方案→专家互评→裁决，冲突以用户红线为准）

### ADR-03: 知识库两分
- 状态: 已采纳
- 决策: 风格库为**刷新型**（调用时先联网检索设计趋势再追加「最近更新」区）；各专家工艺规则（金字塔/六段式/质检清单）为**内置型**
- 理由: 用户澄清时选择「需要（刷新型）」——风格的价值在「捕捉新鲜」；工艺规则的价值在「稳定执行、口径统一」
- 影响: 无网络时风格库回退到固化的 6 风格，仍可工作

### ADR-05: 社区风格扩充 + 换一轮协议（v1.7 补记，用户反馈）
- 状态: 已采纳（2026-08-24）
- 决策: 风格库从 6 种扩到 14 种（新增 swiss-grid/glassmorphism/editorial-magazine/dark-tech/aurora-gradient/flat-illustration/brutalist/retro-y2k，均注明社区来源链接）；新增 `shared/style-switcher.md`（风格选择器：先问方向再给 3-4 个具体选项；换一轮协议：内容保留只换 style_id → 新 plan → 重派 → 新文件不覆盖旧文件 → 附新旧风格对比；最多连续 3 轮）
- 理由: 用户要求「生图和做 PPT 借鉴社区/GitHub 精美个性风格、可选、不满意换一轮」；6 种经典风格偏商务向，缺辨识度；「换一轮」需成一等公民流程而非零散修订
- 备选: 直接抓取社区模板文件入库——被否（版权与维护风险，只借鉴风格规格）
- 影响: 生图技能（office-imagegen）增加 style_id→绘图风格映射，换风格时配图同步重生成，图文统一

## 五、避坑经验

- 文档类工作流最大坑：只设计「新建」不设计「编辑」——澄清时**必问使用方式**，用户提供现有文件时必须有编辑分支
- 三件套共用风格库：风格规格必须给三端落地要点（Word/PPT/Excel 各写一份），否则专家各自发挥、风格不统一
- 数据类文档（Excel）必须锁死统计红线（不杜撰/相关≠因果/小样本不硬下结论），否则 AI 幻觉数据结论
- 修改契约（触发词/元信息/命名）只改根 README + contract-spec.md，各 AGENT.md 保持引用，避免改一处漏一处
- 社区风格借鉴只取「风格规格」（配色/字体/版式原则），不搬模板素材文件——版权与维护双风险
- 「换一轮」必须是一等公民流程（style-switcher.md）：内容保留只换风格 → 新 plan → 重派 → 不覆盖旧文件 → 新旧对比；否则用户会觉得「风格没得选」
