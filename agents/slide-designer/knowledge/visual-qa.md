# PPT 视觉审稿质检（visual-qa）

> 目标：交付前自动 + 人工双重排查「文字溢出、元素重叠、对比度不足、越界、字体缺失」五类视觉瑕疵，把「能打开 ≠ 好看」的静默不合格拦在出稿前。
> 来源：@yejiming/dsh-ppt（AI 视觉审稿、自动纠正溢出/重叠）、liustack/pptwise（实时预览迭代）、dream-num/dsh-univer-office（溢出/重叠检测）——均已提炼为规则，未照搬代码。

## 一、五类瑕疵 + 判定标准

| 瑕疵 | 判定标准 | 检测手段 |
|------|----------|----------|
| 文字溢出 | 文字所需高度 > 文本框高度（全角字宽≈字号、ASCII≈0.52×字号、行高≈1.25×字号） | `scripts/visual-qa.py` 估算 + 渲染缩略图复核 |
| 元素重叠 | 两个文本形状包围盒相交面积 > 较小形状 15% | 脚本几何检测 + 人工确认是否设计意图 |
| 对比度不足 | 文字色 vs 底色对比度 < 2.5:1（WCAG 简化） | 脚本检测 + 人工目检 |
| 越界 | 形状超出页面边界（16:9 或 4:3） | 脚本几何检测 |
| 字体缺失 | 用了目标机大概率没有的字体且未嵌入 | 脚本列字体清单 + 人工确认 |

## 二、自动检测（交付前必跑）

```bash
python office-studio/agents/slide-designer/scripts/visual-qa.py <deck.pptx>
```

- 退出码 `0`：通过；`1`：有告警，逐条处理；`2`：缺 python-pptx，转人工目检。
- 脚本只做「估算 + 几何」两类确定性检查；溢出是估算值，**最终必须**用 LibreOffice headless 或 PowerPoint 渲染缩略图人工复核一遍（见下）。

## 三、人工目检清单（脚本兜底 + 终审，逐条过）

- [ ] 逐页渲染缩略图，确认无文字被文本框裁切/串行到下一元素
- [ ] 标题、正文、图表、图注四层元素互不遮挡（刻意叠放如「文字压在图上」除外，但须可读）
- [ ] 每页文字与背景/色块对比充分，深底用浅字、浅底用深字，无色盲难分配色
- [ ] 字体统一（标题/正文各一种，全文 ≤ 3 种），中文用微软雅黑/思源黑体/宋体等常见字体
- [ ] 元素不贴边出血，安全边距 ≥ 页面宽度的 3%（16:9 约 0.4 英寸）
- [ ] 图表坐标轴标签、图例、数据标签不截断、不重叠

## 四、自动修正规则（检出即改）

1. **溢出**：优先删字/缩句（PPT 铁律：一页一论点，不是排版挤压）；仍放不下则缩小字号一档或拆成两页，**禁止**缩到 12pt 以下硬塞。
2. **重叠**：沿网格错开/缩小/合并，保持对齐；确属设计意图的叠放，给底层加对比或给文字加描边保证可读。
3. **对比度**：换文字色或换底色，使对比度 ≥ 3:1（正文）、≥ 4.5:1（大段文字）。
4. **越界**：重排到安全边距内，或缩小元素。
5. **字体**：统一为 style-catalog 指定字体；若必须用品牌字体，按 brand-kit 规则并提示用户目标机需安装或嵌入。

## 五、与现有质检的关系

- 本文件是 `quality-checklist.md`「无溢出/重叠/字体缺失」一条的**展开方法论**；`pptx-generation-reliability.md` 负责「文件合法性」（能打开、不弹修复框），本文件负责「视觉质量」（打开后好看、可读）。
- 二者互补：先过 reliability（文件合法），再过 visual-qa（视觉合格），最后渲染缩略图人工终审，才算出稿。
