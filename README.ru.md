# office-studio — Мультиагентный рабочий процесс для офисных документов

[English](README.md) · [简体中文](README.zh-CN.md) · [Español](README.es.md) · [Français](README.fr.md) · **[Русский](README.ru.md)** · [日本語](README.ja.md)



> Целевая платформа: **DSH** (данная среда). Один конвейер для эффективного создания и редактирования офисных документов трёх типов — **Word · PPT · Excel** — с приоритетом качества и поддержкой **переключения между несколькими стилями в один клик**.

## I. Конвейер

```
【新建】用户一句话（如"帮我做一份商务风PPT"）
        │
        ▼
orchestrator（大脑·策划调度）──澄清需求+选风格──▶ 产出 outputs/plans/plan-NN.md ──▶ 用户确认
        │                                              │
        │ 派发自包含任务包（含已选风格）                │
        ├──────────────┬──────────────┬────────────────┤
        ▼              ▼              ▼                ▼
   word-crafter   slide-designer  sheet-analyst   （按 doc_type 只派一个）
   （Word撰写·小组） （PPT设计·小组） （Excel报表·单一资深）
        ▼              ▼              ▼
   outputs/word/   outputs/ppt/    outputs/excel/
   doc-NN.docx     deck-NN.pptx    sheet-NN.xlsx
        └──────────────┴──────────────┴────────────────┘
                        │ 汇总汇报
                        ▼
                    orchestrator → 交付用户 → 迭代（send_message 续聊修订）

【编辑】拖入/提供现有文档（.docx/.pptx/.xlsx 路径）
        │
        ▼
orchestrator ──读取识别（结构/风格/内容概要）──▶ 澄清 修改目标/保留项/风格
        │
        ▼ 产出 outputs/plans/edit-NN.md（source_file + change_request + keep）
   对应专家：先读原文件 → 增量修改（保留原结构风格）→ 产出 doc/deck/sheet-NN + 逐条改动清单
        │
        ▼
   交付用户 → 迭代（send_message 续聊修订）
```

## II. Сопоставление триггерных слов

| Агент | Обязанность в одной строке | Триггерные слова (естественный язык, включая синонимичные варианты) |
|--------|-----------|------------------------------|
| **orchestrator** (Мозг) | Принимает требование → выдаёт выбранный стиль + самодостаточный пакет задач → агрегирует результат | Создание: `开始策划` `新建文档` `帮我做一份PPT` `帮我写一份Word` `帮我做一份Excel` `做文档`; Редактирование: `编辑文档` `修改文档` `改这份PPT` `改这个Word` (при наличии существующего файла отдаётся предпочтение ветке редактирования) |
| **word-crafter** | Принимает план + стиль → выдаёт .docx, соответствующий спецификации | Создание: `撰写Word` `写正文` `生成Word`; Редактирование: `改Word` `修改文档` `编辑这份Word` |
| **slide-designer** | Принимает план + стиль → выдаёт повествовательный .pptx | Создание: `制作PPT` `做幻灯片` `生成PPT`; Редактирование: `改PPT` `修改这份PPT` |
| **sheet-analyst** | Принимает данные + план + стиль → выдаёт .xlsx с выводами в начале | Создание: `制作Excel` `做报表` `生成Excel` `分析数据`; Редактирование: `改Excel` `修改表格` `编辑这份Excel` |

**Правила триггеров**: Новые задачи (без соответствующего архива планов) всегда сначала попадают к `orchestrator` для уточнения; после того как `plan-NN.md` подтверждён пользователем, используйте выделенные триггерные слова каждого эксперта, чтобы обращаться напрямую. Триггерные слова не конфликтуют ни между собой, ни со встроенными системными командами.

## IV. Контракты файлов (выход вышестоящего этапа → читается нижестоящим)

1. **Планирование → каждому эксперту (создание)**: `outputs/plans/plan-NN.md` с фиксированным форматом метаданных в шапке:
   ```yaml
   ---
   doc_id: plan-NN
   title: <заголовок>
   doc_type: word | ppt | excel
   style_id: <см. shared/style-catalog.md — 14 стилей: 6 классических + 8 вдохновлённых сообществом; выбор — в shared/style-switcher.md>
   brand_kit: <необязательно; записывайте brand-NN, когда пользователь предоставляет фирменные материалы; правила — в shared/brand-kit.md; при отсутствии опустите>
   audience: <аудитория>
   purpose: <цель>
   length: <объём>
   data_source: <необязательно, путь к файлу данных Excel>
   ---
   ```
1b. **Задача редактирования → каждому эксперту (редактирование)**: `outputs/plans/edit-NN.md`:
   ```yaml
   ---
   doc_id: edit-NN
   source_file: <путь к исходному документу, предоставленному/перетащенному пользователем>
   doc_type: word | ppt | excel
   mode: edit
   change_request: <запрос на изменение, с указанием абзаца/страницы/ячейки>
   keep: <обязательные к сохранению элементы: исходное форматирование / существующие выводы / данные>
   style_id: <по умолчанию — исходный стиль; смена стиля требует явного указания пользователем>
   ---
   ```
2. **Результат каждого эксперта**: `outputs/<type>/<filename>` с одноимённым файлом `-meta.md` (фиксирует: doc_id, style_id, **brand_kit (при наличии)**, дату генерации, источник данных, заметки об изменениях).
3. **Итерация**: Все замечания пользователя по доработке проходят через `send_message` в DSH, чтобы продолжить диалог атомарного агента для правки с сохранением контекста; правки должны записываться в «заметки об изменениях» файла `-meta.md` и никогда не перезаписывать молча подтверждённое содержимое.
4. **Бренд-кит (v2)**: Когда пользователь предоставляет фирменные материалы (фирменные цвета / логотип / шрифты / шаблоны) → orchestrator собирает их в `shared/brand-kit.md`, в плане записывается `brand_kit: brand-NN`, и все три эксперта применяют их единообразно (бренд имеет приоритет над каталогом стилей); при выпуске нескольких документов под одним brand_id orchestrator проверяет согласованность бренда (см. `shared/brand-kit.md`).

## V·5 Повторное использование чертежа

Существующий чертёж: **办公文档** (`blueprints/办公文档.md`, содержит топологическую схему / список агентов / записи решений ADR / переиспользуемые части из сообщества / извлечённые уроки). Для похожих задач (мультиагентные рабочие процессы документного типа) можно сказать 「**复用 办公文档 拓扑**」 — нужно лишь уточнить отличия, без перепроектирования; итеративные изменения записываются обратно и в чертёж, и в этот документ.

## VI. Инструкции по первому запуску

1. Новая задача: просто скажите 「**帮我做一份[PPT/Word/Excel]**」 или 「**开始策划**», и orchestrator спросит о теме / аудитории / объёме / стиле, **а также спросит, есть ли фирменные материалы (если да — оформляйте единообразно согласно бренд-киту)**.
2. Выбор стиля: orchestrator сначала спрашивает направление (стабильно-профессиональное / современное премиальное / выразительно-индивидуальное / дружелюбно-контентное), затем предлагает 3–4 конкретных варианта стиля (14 стилей: Деловой профессиональный / Маккинзи / Академический / Минимализм / Креативный / Официальный + Швейцарская сетка / Глассморфизм / Журнально-редакционный / Тёмный техно / Градиент авроры / Плоская иллюстрация / Брутализм / Ретро Y2K) со ссылками на источники из сообщества для справки.
3. После подтверждения плана произнесите соответствующее триггерное слово эксперта (например, 「制作PPT」), чтобы создать документ.
4. Изменение (уже созданного документа): просто скажите, что изменить, и orchestrator с помощью `send_message` попросит атомарного агента продолжить диалог для правки.
5. **Не устраивает стиль? Смените за один раунд**: просто скажите 「换一种风格/风格不满意/换个风格重做」 — содержимое и структура полностью сохраняются, orchestrator заново предлагает варианты стиля, создаёт новый план с новым `style_id` и переделывает работу; новый файл не перезаписывает старый, а в поставку включается сравнение стиля «до/после». Рекомендуется не более 3 раундов подряд, затем перейти к тонкой доработке деталей или предоставить эталонное изображение.
6. **Редактирование существующего документа**: отправьте мне путь к .docx/.pptx/.xlsx (или перетащите файл) и скажите 「**改这个Word / 改这份PPT / 修改表格** + что изменить»; orchestrator сначала определяет структуру/стиль исходного документа, затем эксперт вносит инкрементальные изменения, а в поставку включается постатейный список изменений без перезаписи исходного файла.

## VIII. Улучшения возможностей PPT в v3 (2026, выжимка после изучения 7 PPT-плагинов сообщества)

> Заимствуя **механизмы** (но не код) из dsh-ppt / PPTKit Presentation / @yejiming/dsh-ppt / pptfast / pptwise / DeepSeek Design / dsh-univer-office, slide-designer добавляет четыре возможности:

- **Визуальный контроль качества (QA)**: `agents/slide-designer/scripts/visual-qa.py` автоматически обнаруживает переполнение текста / наложение элементов / недостаточный контраст / выход за границы / отсутствующие шрифты (`python visual-qa.py <deck.pptx>`); `knowledge/visual-qa.md` содержит чек-лист ручной проверки и правила автоисправления.
- **Совместная работа с экосистемой плагинов**: `knowledge/plugin-ecosystem.md` фиксирует команды установки и режимы взаимодействия 7 PPT-плагинов сообщества (этот навык создаёт первый нарративный черновик → плагины занимаются доработкой визуализации / рецензированием).
- **Сопоставление псевдонимов тем**: в `shared/style-catalog.md` добавлены соответствия названий тем сообщества к `style_id` («Дрейф данных» → `dark-tech`, «Швейцарский пульс» → `swiss-grid`, «Бархатный стандарт» → `editorial-magazine` и т. д.).
- **Улучшения**: сначала спецификация (постраничные спецификации финализируются до отрисовки), двойные артефакты HTML-превью, извлечение цветов/шрифтов из существующих PPT компании в бренд-кит.
